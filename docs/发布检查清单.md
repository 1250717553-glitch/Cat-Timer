# 发布检查清单（桌面宠物计时器 1.0）

> **这份清单存在的理由**：2026-10-28 曾出现一次「新瓶装旧酒」——
> `dist/` 里是 10-09 的旧程序，`ISCC` 却按当天时间编译出了看起来全新的
> `Setup.exe`。安装包能编译成功，**不代表里面装的是新程序**。
> 本清单把「打包」和「验证包里装了什么」拆成两个独立步骤，缺一不可。

按顺序执行，**任何一步失败就停下**，不要带着失败往下走。

---

## 0. 环境前置

| 检查 | 命令 | 期望 |

| 虚拟环境 | `ls .venv/Scripts/python.exe` | 存在 |
| PySide6 | `.venv/Scripts/python.exe -c "import PySide6; print(PySide6.__version__)"` | 6.12.0 |

> `"$LOCALAPPDATA/Programs/Inno Setup 6/ISCC.exe"`

## 0.5 ⚠️ 数据安全铁律（任何脚本/测试都适用）

**任何会创建 `MainWindow`、调用 `save_events`、或构造 `Event` 的脚本或测试，
必须在导入任何 `core` 模块之前先隔离 `APPDATA`：**

```python
import os, tempfile
os.environ["APPDATA"] = tempfile.mkdtemp(prefix="dpt_test_")
```

> **为什么这条是铁律**：2026-10-29 发生过一次真实数据丢失 ——
> 某个测试文件忘了隔离，把它的测试 fixture 写进了用户真实的
> `%APPDATA%\桌面宠物计时器\config.json`，**用户自己的事件被永久覆盖**，
> 且当时没有备份机制，无法恢复。

现状：17 个 `test_*.py` 的文件头都已内联这三行隔离代码，
`tests/test_env_isolation.py` 有 3 条守护测试盯着它。
**新增测试文件时必须照抄这三行**（守护测试只检查当前进程，不会替你检查新文件）。

### 为什么不用 `tests/__init__.py`

`unittest discover` 把 `tests/` 当**纯目录**、按顶层模块名逐个加载
（测试 id 形如 `test_xxx.TestClass`，没有 `tests.` 前缀），
`__init__.py` 里的代码**根本不会执行**——实测验证过。
所以只能每个文件自己 import 一次。

### 损坏配置的备份

`core/paths.py` 的 `backup_corrupt_file()` 用 **rename** 把损坏文件隔离成
`.corrupt-<时间戳>.json`。三处加载函数（config / preferences / floating_window）
都在解析失败时调用它。

**rename 而非 copy 的理由**：copy 的话原文件还在，下次启动又读到同样的损坏内容，
反复报错；rename 之后原路径空出，程序能正常写入新配置，自愈。

## 1. 单元测试

```bash
export APPDATA=$(mktemp -d)      # 绝不能跑真实用户配置
export QT_QPA_PLATFORM=offscreen
.venv/Scripts/python.exe -m unittest discover -s tests
```

期望：`OK`，且**如实记录用例数**（1.0 收尾时为 151）。

## 2. 心跳不变量

```bash
.venv/Scripts/python.exe tools/verify_heartbeat.py
```

期望：`[PASS]`。这条验证的是「全程序只有一个 1 秒节拍」——
悬浮窗不得持有自己的刷新定时器。

## 3. 退出冒烟（开发期）

```bash
.venv/Scripts/python.exe tools/check_quit.py --dev
```

期望：`[PASS]`，退出码 0。
这条验证「点退出真的退出」，防的是 `closeEvent` 里 `ignore()` 导致
`app.quit()` 静默失效。

---

## 4. PyInstaller 打包

```bash
rm -rf build dist            # 必须先清！否则旧产物会叠加，看不出差异
.venv/Scripts/python.exe -m PyInstaller build.spec --noconfirm
```

期望：`Build complete`。

> **不要只看 `Build complete`**。历史上这里出过两次问题：
> 一次是沙箱拦截 `rmdir` 导致新产物叠在旧目录上（体积一直降不下来）；
> 一次就是「没重新打包，直接编译了安装包」。

---

## 5. ⚠️ 验证 assets 真的入包了（本清单最重要的一步）

```bash
ls -l "dist/桌面宠物计时器/_internal/assets/tray.ico"
ls -l "dist/桌面宠物计时器/_internal/assets/pet/body.png"
```

期望：两个文件都存在。

再核对**程序本体是不是新的**（这一条能拦住「新瓶装旧酒」）：

```bash
ls -l --time-style=+%Y-%m-%d_%H:%M "dist/桌面宠物计时器/桌面宠物计时器.exe"
date
```

期望：exe 时间戳是**刚刚**，不是几天前。

> 2026-10-28 的失误正是跳过了这一步：`assets` 在 `dist` 里零命中，
> 而 `Setup.exe` 的时间戳是当天 —— 一个「看起来新」的旧程序。

## 7. 编译安装包

```bash
"$LOCALAPPDATA/Programs/Inno Setup 6/ISCC.exe" installer.iss
```

期望：`Successful compile` + `dist/Setup.exe`。

核对压缩条目数应与便携版文件数一致：

```bash
find "dist/桌面宠物计时器" -type f | wc -l
```

> `installer.iss` 现在用 `PrivilegesRequired=lowest` +
> `DefaultDirName={localappdata}\Programs\...`，装到用户目录，不弹 UAC。

## 8. 安装（必须在交互式桌面，人工执行）

1. 双击 `dist/Setup.exe`
2. 期望：**不弹 UAC**（因为是 lowest 权限）
3. 安装路径应为 `%LocalAppData%\Programs\桌面宠物计时器\`
4. 勾选「立即运行」或从开始菜单启动

---

## 9. 启动检查（人工，逐条确认）

| 项 | 期望 |
|---|---|
| 托盘图标 | **是一只猫**，不是 Windows 默认显示器图标 |
| 悬浮窗宠物 | **是真实照片素材**，不是程序画的占位猫 |
| 倒计时跳动 | 每秒更新，主窗口与悬浮窗**同步** |
| 关闭主窗口 | 进程仍在（托盘可见），提醒仍会触发 |
| 多显示器 | 把悬浮窗拖到副屏，重启后位置保持 |
| 右键菜单 | 新增 / 管理 / 稍后提醒 / 隐藏 / 退出齐全 |
| 退出 | 点退出后进程真的结束（任务管理器无残留） |

> 只要托盘是显示器图标、或宠物是几何占位猫，就说明第 5 步被跳过了。
